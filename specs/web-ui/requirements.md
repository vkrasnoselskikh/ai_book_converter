# Requirements Document: AI Book Converter Web UI

## Introduction

The system must provide a single-page web application named "AI Book converter". When a user opens the site, they must immediately receive an anonymous session identifier and be able to upload a book in PDF or DJVU format, view the extracted metadata and cover, edit them, and preview the book in the browser without signing in first. The system must store anonymous sessions, users, external authentication identities, books, book metadata, and book access links, and it must keep book processing files in a stable directory tied to the book identifier.

## Glossary

- **Anonymous session** - a UUID identifier issued to a visitor before authentication and used to keep that visitor's current book work available.
- **User** - an authenticated person or system actor that can own one or more books.
- **Authentication identity** - an external identity from Google, Facebook, or Telegram that can be linked to one user account.
- **Book** - the uploaded source file and its related processing results.
- **Book metadata** - title, authors, language, description, table of contents, and other data extracted from the file or edited by the user.
- **Table of contents** - a list of book sections that links to page anchors in the preview.
- **Page anchor** - a stable identifier tied to an original book page and used as a hyperlink target in preview content.
- **Cover** - the book image extracted from the file, generated by the system, or uploaded by the user.
- **Book preview** - browser rendering of the book content without navigating to another application page.
- **Processing files** - the source file, extracted cover, intermediate data, prepared HTML, and other processing artifacts.
- **User-book link** - a record showing that a book is available to a specific authenticated user.
- **Session-book link** - a record showing that a book is available to a specific anonymous session before authentication.

## Requirements

### 1. Single-Page User Interface

**ID:** web-ui.1

**User Story:** As a user, I want to open the site and immediately see the upload and preview interface so that I can start working without extra navigation.

#### Acceptance Criteria

1.1. WHEN the user opens the site, the system SHALL display the single-page application "AI Book converter".
1.1.1. WHEN the user opens the site without an existing valid session, the system SHALL issue an anonymous session identifier.
1.1.2. WHEN the user opens the site with an existing valid session, the system SHALL reuse that anonymous session identifier.
1.2. The single-page application SHALL contain a header bar.
1.2.1. The header bar SHALL contain a left area with the application icon and title "AI Book converter".
1.2.2. The header bar SHALL contain a left area book selector block showing the current book when a book is selected.
1.2.3. WHEN a book is selected, the book selector block SHALL show the current book label in the form "Book: <book title or file name>".
1.2.4. The header bar SHALL contain a right area with a profile icon button.
1.2.5. WHEN the user activates the profile icon button, the system SHALL open a dropdown menu with profile settings.
1.2.6. IF no book is selected, the book selector block SHALL show an empty or neutral current-book state without breaking the header layout.
1.3. The single-page application SHALL contain a book upload block.
1.4. The single-page application SHALL contain a block for extracted metadata and cover.
1.5. The single-page application SHALL contain a book preview block.
1.6. The single-page application SHALL contain a footer.
1.7. WHILE no book data has been loaded, the metadata and preview blocks SHALL display empty states without errors.
1.8. WHEN the user changes the system or application color scheme, the system SHALL support day and night display modes.

#### Functional Tests

- `apps/web-ui/tests/functional/test_home_page.ts` - "renders the main blocks of the single-page application".
- `apps/web-ui/tests/functional/test_header_layout.ts` - "renders the header brand, current book selector, and profile menu".
- `apps/web-ui/tests/functional/test_theme_modes.ts` - "switches day and night modes without losing page state".

### 2. Book Upload

**ID:** web-ui.2

**User Story:** As a user, I want to upload a book in EPUB or DJVU format so that the system can read its content and prepare it for preview.

#### Acceptance Criteria

2.1. WHEN the user selects a book file, the system SHALL accept files with the EPUB extension.
2.2. WHEN the user selects a book file, the system SHALL accept files with the DJVU extension.
2.3. IF the user selects an unsupported file format, the system SHALL show a clear error and SHALL NOT create a book.
2.4. WHEN the user submits a supported file, the system SHALL create a book record.
2.5. WHEN the book is created, the system SHALL assign it a unique UUID identifier.
2.6. WHEN the book is created, the system SHALL save the source file and processing files in the book directory.
2.7. IF file processing fails, the system SHALL save a diagnostic book status and show a clear message to the user.
2.8. WHEN the book is created after upload, the system SHALL update the browser address bar to the canonical processing URL for this book.
2.9. WHEN the browser address bar is updated to the book processing URL, the system SHALL NOT require book processing to be completed.
2.10. WHEN the uploaded book file name contains non-ASCII characters, the system SHALL preserve the readable file name in the current book label and book history.

#### Functional Tests

- `apps/web-ui/tests/functional/test_book_upload.ts` - "uploads PDF and DJVU".
- `apps/web-ui/tests/functional/test_book_upload.ts` - "preserves non-ASCII uploaded file names".
- `apps/web-ui/tests/functional/test_upload_validation.ts` - "rejects an unsupported format".
- `apps/web-ui/tests/functional/test_book_processing_url.ts` - "updates the address bar to the book processing URL after upload".

### 3. Metadata and Cover

**ID:** web-ui.3

**User Story:** As a user, I want to see the extracted book metadata and cover and then correct them when needed so that the book card is accurate.

#### Acceptance Criteria

3.1. WHEN book processing finishes reading metadata, the system SHALL show the detected data in the metadata block.
3.2. WHEN book processing finds a cover, the system SHALL show it in the cover block.
3.3. IF no cover is found, the system SHALL show a missing-cover state and allow the user to add one manually.
3.4. WHEN the user edits metadata, the system SHALL save the changed values.
3.5. WHEN the user replaces the cover, the system SHALL save the new cover as the current book cover.
3.6. IF saving metadata or cover fails, the system SHALL preserve the previous data and show a clear message.
3.7. WHEN the system extracts metadata with the metadata agent, the agent SHALL use the first three pages of the book as input.
3.8. WHEN metadata extraction succeeds, the system SHALL store the title, authors, ISBN numbers, language, cover subtitle, and cover image.
3.9. IF the metadata agent does not detect a language, the system SHALL use "en" as the default language.
3.10. WHEN PDF or DJVU OCR processing can render the first document page as an image, the system SHALL save that first-page image as the current cover.
3.11. IF first-page cover rendering is unavailable during OCR processing, the system SHALL use an available OCR image from the first page as the cover.

#### Functional Tests

- `apps/web-ui/tests/functional/test_book_metadata.ts` - "shows and saves book metadata".
- `apps/web-ui/tests/functional/test_cover_editing.ts` - "shows, replaces, and saves the book cover".
- `apps/web-ui/tests/functional/test_metadata_agent.ts` - "extracts metadata from the first three pages".

### 4. Book Preview

**ID:** web-ui.4

**User Story:** As a user, I want to preview the uploaded book on the same page so that I can quickly check the processing result.

#### Acceptance Criteria

4.1. WHEN the book has been processed, the system SHALL display book content in the preview block.
4.2. WHEN book content contains chapters or a table of contents, the system SHALL allow navigation to available structural parts.
4.3. WHEN book content contains images, the system SHALL display them near the related text.
4.4. WHEN book content contains tables, the system SHALL display them as part of the book content.
4.5. WHEN book content contains footnotes, the system SHALL preserve them in readable form.
4.6. WHILE the book is being processed, the system SHALL show a processing state instead of an empty preview.
4.7. IF preview preparation fails, the system SHALL show a diagnostic message without breaking the other page blocks.
4.8. WHEN the system displays a table of contents, each entry SHALL link to a page anchor.
4.9. WHEN the system displays a table of contents, the system SHALL NOT show raw page numbers as the navigation target.
4.10. WHEN the user opens a valid book processing URL, the system SHALL show the current processing state for that book.
4.11. WHEN the user opens a valid book processing URL after processing has completed, the system SHALL show the editable metadata, cover, and preview for that book.
4.12. WHILE a book is being processed, the user SHALL be able to leave the browser tab and later return to the same book processing URL.
4.13. WHEN the system renders article preview content, it SHALL apply readable article styling to headings, links, lists, code blocks, tables, quotes, and images.

#### Functional Tests

- `apps/web-ui/tests/functional/test_book_reader.ts` - "shows a processed book with text, images, and tables".
- `apps/web-ui/tests/functional/test_book_processing_state.ts` - "shows the processing state and preview preparation error".
- `apps/web-ui/tests/functional/test_table_of_contents.ts` - "shows table of contents links to page anchors".
- `apps/web-ui/tests/functional/test_book_processing_resume.ts` - "reopens a book processing URL and resumes status or editing".

### 5. Users and Book Access

**ID:** web-ui.5

**User Story:** As a user, I want to see books available to my current session or user account so that I can start anonymously and keep history after authentication.

#### Acceptance Criteria

5.0. WHILE the user is not authenticated, the system SHALL allow book upload, metadata editing, cover editing, and preview through the anonymous session.
5.1. The system SHALL store users.
5.2. The system SHALL store books.
5.3. The system SHALL store book metadata.
5.4. The system SHALL store links between users and books.
5.5. WHEN one book is available to several users, the system SHALL store one book record and several ownership links.
5.6. WHEN an anonymous user opens the application, the system SHALL show only books available to the current anonymous session.
5.7. WHEN an authenticated user opens the application, the system SHALL show only books available to the current user account.
5.8. For all session, user, book, identity, and link records, the system SHALL use UUID as the identifier.
5.9. WHEN an authenticated user has processed books, the system SHALL keep those books in the user's processing history.

#### Functional Tests

- `apps/web-ui/tests/functional/test_anonymous_books.ts` - "shows books for the current anonymous session".
- `apps/web-ui/tests/functional/test_user_books.ts` - "shows books for the authenticated user".
- `apps/web-ui/tests/functional/test_shared_books.ts` - "links one book to several users without duplicating the book".

### 6. Processing File Storage

**ID:** web-ui.6

**User Story:** As a system owner, I want processing files for each book to be stored in a separate directory so that data can be diagnosed, reprocessed, and migrated.

#### Acceptance Criteria

6.1. WHEN a book is created, the system SHALL create a processing file directory for this book.
6.2. The book processing file directory SHALL be located at `AI_BOOK_COVERTER_BOOKS_PATH/<book_id>`.
6.3. WHEN the system saves the source file, it SHALL place it in the processing file directory for the related book.
6.4. WHEN the system saves the cover, it SHALL place it in the processing file directory for the related book.
6.5. WHEN the system saves intermediate processing data, it SHALL place it in the processing file directory for the related book.
6.6. IF the processing file directory is unavailable, the system SHALL stop book processing with a diagnostic status.

#### Functional Tests

- `apps/web-ui/tests/functional/test_book_file_storage.ts` - "creates the book directory and saves processing artifacts".
- `apps/web-ui/tests/functional/test_book_storage_error.ts` - "shows a diagnostic status when the directory is unavailable".

### 7. Server-Side Rendering and First Screen Availability

**ID:** web-ui.7

**User Story:** As a user, I want to receive the first application screen from the server quickly so that the upload interface is available immediately after opening the site.

#### Acceptance Criteria

7.1. WHEN the user requests the home page, the system SHALL return server-rendered HTML for the first screen.
7.2. WHEN the client code has loaded, the system SHALL continue application behavior without a page reload.
7.3. IF client hydration has not completed yet, the system SHALL preserve access to the header bar, upload block, and footer.
7.4. IF server preparation of the first screen fails, the system SHALL return a diagnostic page without exposing internal secrets.
7.5. WHEN the user requests a book processing URL directly, the system SHALL return server-rendered HTML for the book workspace.
7.6. IF the requested book is not available to the current anonymous session or authenticated user, the system SHALL show a safe not-found or access-denied state.

### 8. Converter Logic Port

**ID:** web-ui.8

**User Story:** As a user, I want the web application to use the behavior of the current converter so that book processing preserves the already implemented normalization and rendering rules.

#### Acceptance Criteria

8.1. WHEN the system processes a book, it SHALL use the validation rules for formats supported by the web requirements.
8.2. WHEN the system receives structured book content from Mistral OCR, it SHALL attach a stable page anchor to each recognized page.
8.3. WHEN the system processes images, it SHALL save images and link them to the related pages or content blocks.
8.4. WHEN the system processes tables, it SHALL preserve them as part of the book content.
8.5. WHEN the system processes footnotes, it SHALL preserve them in readable form and SHALL NOT lose unmatched footnotes.
8.6. WHEN the system prepares HTML for preview, it SHALL preserve the content order of the source book.
8.7. IF input or intermediate data is incomplete, the system SHALL continue processing available parts and save warnings.
8.8. WHEN the system sends a document to Mistral OCR, it SHALL use the same OCR behavior as the current JS live OCR flow.
8.9. WHEN the system normalizes OCR page content, it SHALL separate service header and footer blocks from the main text.
8.10. WHEN the table-of-contents agent runs, it SHALL use pages 1 through 20 of the book as input.
8.11. WHEN the table-of-contents agent returns entries, each entry SHALL contain a title and a hyperlink target page anchor.
8.12. WHEN the table-of-contents agent returns entries, entries SHALL NOT use raw page numbers as the user-facing navigation target.
8.13. WHEN OCR images are saved, the system SHALL persist and render them with stable filenames that match the preview and EPUB image references.
8.14. WHEN preview content is rendered from OCR pages, the system SHALL use one-based page anchors that match table-of-contents links.
8.15. WHEN the table-of-contents agent reads an entry from a table-of-contents page, the system SHALL create the page anchor from the target page number printed in the table-of-contents text.
8.15.1. WHEN a table-of-contents entry is found on one book page and points to a different printed target page number, the system SHALL link the entry to the printed target page anchor.
8.16. WHEN the table-of-contents agent runs, it SHALL identify the source page range where the printed table of contents starts and ends when such a range is present.
8.17. WHEN OCR-derived final preview and book artifacts are prepared, the system SHALL exclude pages classified as table-of-contents pages.
8.17.1. IF the table-of-contents agent does not return a valid table-of-contents page range, the system SHALL keep OCR pages in the final preview and book artifacts.
8.18. WHEN OCR-derived EPUB artifacts are generated from markdown content, the system SHALL preserve readable lists, tables, code blocks, blockquotes, links, images, and inline formatting.

#### Functional Tests

- `apps/web-ui/tests/functional/test_converter_port.ts` - "preserves the current converter normalization rules in the web flow".
- `apps/web-ui/tests/functional/test_partial_book_data.ts` - "processes partial data without losing diagnostic warnings".
- `apps/web-ui/tests/functional/test_ocr_page_anchors.ts` - "adds page anchors to OCR pages".
- `apps/web-ui/tests/functional/test_toc_agent.ts` - "creates table of contents links from pages 1 through 20 and removes detected table-of-contents pages".

### 9. Authentication and Session-to-Account Linking

**ID:** web-ui.9

**User Story:** As a user, I want to authenticate after starting work anonymously so that my current books and edits become part of my account history.

#### Acceptance Criteria

9.1. WHERE Google authentication is configured, the system SHALL allow the user to authenticate with Google.
9.2. WHERE Facebook authentication is configured, the system SHALL allow the user to authenticate with Facebook.
9.3. WHERE Telegram authentication is configured, the system SHALL allow the user to authenticate with Telegram.
9.4. WHEN authentication succeeds for an identity that is already linked to an existing user account, the system SHALL use that existing user account.
9.5. WHEN authentication succeeds for an identity that is not linked to an existing user account, the system SHALL create a new user account and link the identity to it.
9.6. WHEN an anonymous session has books and the user authenticates successfully, the system SHALL link the anonymous session's books and saved edits to the authenticated user account.
9.7. WHEN a session book is linked to an authenticated account that already has access to the same book, the system SHALL NOT create a duplicate book record.
9.8. WHEN session-to-account linking completes, the authenticated user's processing history SHALL include books processed during the anonymous session.
9.9. IF session-to-account linking fails, the system SHALL keep the anonymous session data available and show a clear diagnostic message.

#### Functional Tests

- `apps/web-ui/tests/functional/test_auth_providers.ts` - "starts Google, Facebook, and Telegram authentication when configured".
- `apps/web-ui/tests/functional/test_session_account_linking.ts` - "links anonymous books to a new or existing user after authentication".
- `apps/web-ui/tests/functional/test_authenticated_history.ts` - "shows authenticated processing history after session linking".
