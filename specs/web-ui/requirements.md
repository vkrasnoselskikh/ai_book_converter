# Requirements Document: AI Book Converter Web UI

## Introduction

The system must provide a single-page web application named "AI Book converter". When a user opens the site, they must immediately be able to upload a book in EPUB or DJVU format, view the extracted metadata and cover, edit them, and preview the book in the browser. The system must store users, books, book metadata, and user-book ownership links, and it must keep book processing files in a stable directory tied to the book identifier.

## Glossary

- **User** - a person or system actor that can own one or more books.
- **Book** - the uploaded source file and its related processing results.
- **Book metadata** - title, authors, language, description, table of contents, and other data extracted from the file or edited by the user.
- **Cover** - the book image extracted from the file, generated by the system, or uploaded by the user.
- **Book preview** - browser rendering of the book content without navigating to another application page.
- **Processing files** - the source file, extracted cover, intermediate data, prepared HTML, and other processing artifacts.
- **User-book link** - a record showing that a book is available to a specific user.

## Requirements

### 1. Single-Page User Interface

**ID:** web-ui.1

**User Story:** As a user, I want to open the site and immediately see the upload and preview interface so that I can start working without extra navigation.

#### Acceptance Criteria

1.1. WHEN the user opens the site, the system SHALL display the single-page application "AI Book converter".
1.2. The single-page application SHALL contain a header bar.
1.3. The single-page application SHALL contain a book upload block.
1.4. The single-page application SHALL contain a block for extracted metadata and cover.
1.5. The single-page application SHALL contain a book preview block.
1.6. The single-page application SHALL contain a footer.
1.7. WHILE no book data has been loaded, the metadata and preview blocks SHALL display empty states without errors.
1.8. WHEN the user changes the system or application color scheme, the system SHALL support day and night display modes.

#### Functional Tests

- `apps/web-ui/tests/functional/test_home_page.ts` - "renders the main blocks of the single-page application".
- `apps/web-ui/tests/functional/test_theme_modes.ts` - "switches day and night modes without losing page state".

### 2. Book Upload

**ID:** web-ui.2

**User Story:** As a user, I want to upload a book in EPUB or DJVU format so that the system can read its content and prepare it for preview.

#### Acceptance Criteria

2.1. WHEN the user selects a book file, the system SHALL accept files with the EPUB extension.
2.2. WHEN the user selects a book file, the system SHALL accept files with the DJVU extension.
2.3. IF the user selects an unsupported file format, the system SHALL show a clear error and SHALL NOT create a book.
2.4. WHEN the user submits a supported file, the system SHALL create a book record.
2.5. WHEN the book is created, the system SHALL assign it a unique UUID identifier.
2.6. WHEN the book is created, the system SHALL save the source file and processing files in the book directory.
2.7. IF file processing fails, the system SHALL save a diagnostic book status and show a clear message to the user.

#### Functional Tests

- `apps/web-ui/tests/functional/test_book_upload.ts` - "uploads EPUB and DJVU".
- `apps/web-ui/tests/functional/test_upload_validation.ts` - "rejects an unsupported format".

### 3. Metadata and Cover

**ID:** web-ui.3

**User Story:** As a user, I want to see the extracted book metadata and cover and then correct them when needed so that the book card is accurate.

#### Acceptance Criteria

3.1. WHEN book processing finishes reading metadata, the system SHALL show the detected data in the metadata block.
3.2. WHEN book processing finds a cover, the system SHALL show it in the cover block.
3.3. IF no cover is found, the system SHALL show a missing-cover state and allow the user to add one manually.
3.4. WHEN the user edits metadata, the system SHALL save the changed values.
3.5. WHEN the user replaces the cover, the system SHALL save the new cover as the current book cover.
3.6. IF saving metadata or cover fails, the system SHALL preserve the previous data and show a clear message.

#### Functional Tests

- `apps/web-ui/tests/functional/test_book_metadata.ts` - "shows and saves book metadata".
- `apps/web-ui/tests/functional/test_cover_editing.ts` - "shows, replaces, and saves the book cover".

### 4. Book Preview

**ID:** web-ui.4

**User Story:** As a user, I want to preview the uploaded book on the same page so that I can quickly check the processing result.

#### Acceptance Criteria

4.1. WHEN the book has been processed, the system SHALL display book content in the preview block.
4.2. WHEN book content contains chapters or a table of contents, the system SHALL allow navigation to available structural parts.
4.3. WHEN book content contains images, the system SHALL display them near the related text.
4.4. WHEN book content contains tables, the system SHALL display them as part of the book content.
4.5. WHEN book content contains footnotes, the system SHALL preserve them in readable form.
4.6. WHILE the book is being processed, the system SHALL show a processing state instead of an empty preview.
4.7. IF preview preparation fails, the system SHALL show a diagnostic message without breaking the other page blocks.

#### Functional Tests

- `apps/web-ui/tests/functional/test_book_reader.ts` - "shows a processed book with text, images, and tables".
- `apps/web-ui/tests/functional/test_book_processing_state.ts` - "shows the processing state and preview preparation error".

### 5. Users and Book Ownership

**ID:** web-ui.5

**User Story:** As a user, I want to see books available to my user account so that one book can be linked to several users without duplicating book data.

#### Acceptance Criteria

5.1. The system SHALL store users.
5.2. The system SHALL store books.
5.3. The system SHALL store book metadata.
5.4. The system SHALL store links between users and books.
5.5. WHEN one book is available to several users, the system SHALL store one book record and several ownership links.
5.6. WHEN a user opens the application, the system SHALL show only books available to the current user.
5.7. For all user, book, and link records, the system SHALL use UUID as the identifier.

#### Functional Tests

- `apps/web-ui/tests/functional/test_user_books.ts` - "shows books for the current user".
- `apps/web-ui/tests/functional/test_shared_books.ts` - "links one book to several users without duplicating the book".

### 6. Processing File Storage

**ID:** web-ui.6

**User Story:** As a system owner, I want processing files for each book to be stored in a separate directory so that data can be diagnosed, reprocessed, and migrated.

#### Acceptance Criteria

6.1. WHEN a book is created, the system SHALL create a processing file directory for this book.
6.2. The book processing file directory SHALL be located at `AI_BOOK_COVERTER_BOOKS_PATH/<book_id>`.
6.3. WHEN the system saves the source file, it SHALL place it in the processing file directory for the related book.
6.4. WHEN the system saves the cover, it SHALL place it in the processing file directory for the related book.
6.5. WHEN the system saves intermediate processing data, it SHALL place it in the processing file directory for the related book.
6.6. IF the processing file directory is unavailable, the system SHALL stop book processing with a diagnostic status.

#### Functional Tests

- `apps/web-ui/tests/functional/test_book_file_storage.ts` - "creates the book directory and saves processing artifacts".
- `apps/web-ui/tests/functional/test_book_storage_error.ts` - "shows a diagnostic status when the directory is unavailable".

### 7. Server-Side Rendering and First Screen Availability

**ID:** web-ui.7

**User Story:** As a user, I want to receive the first application screen from the server quickly so that the upload interface is available immediately after opening the site.

#### Acceptance Criteria

7.1. WHEN the user requests the home page, the system SHALL return server-rendered HTML for the first screen.
7.2. WHEN the client code has loaded, the system SHALL continue application behavior without a page reload.
7.3. IF client hydration has not completed yet, the system SHALL preserve access to the header bar, upload block, and footer.
7.4. IF server preparation of the first screen fails, the system SHALL return a diagnostic page without exposing internal secrets.

#### Functional Tests

- `apps/web-ui/tests/functional/test_ssr_rendering.ts` - "returns first-screen HTML from the server".
- `apps/web-ui/tests/functional/test_client_hydration.ts` - "hydrates the application without losing state".

### 8. Converter Logic Port

**ID:** web-ui.8

**User Story:** As a user, I want the web application to use the behavior of the current converter so that book processing preserves the already implemented normalization and rendering rules.

#### Acceptance Criteria

8.1. WHEN the system processes a book, it SHALL use the validation rules for formats supported by the web requirements.
8.2. WHEN the system receives structured book content, it SHALL separate service header and footer blocks from the main text.
8.3. WHEN the system processes images, it SHALL save images and link them to the related pages or content blocks.
8.4. WHEN the system processes tables, it SHALL preserve them as part of the book content.
8.5. WHEN the system processes footnotes, it SHALL preserve them in readable form and SHALL NOT lose unmatched footnotes.
8.6. WHEN the system prepares HTML for preview, it SHALL preserve the content order of the source book.
8.7. IF input or intermediate data is incomplete, the system SHALL continue processing available parts and save warnings.

#### Functional Tests

- `apps/web-ui/tests/functional/test_converter_port.ts` - "preserves the current converter normalization rules in the web flow".
- `apps/web-ui/tests/functional/test_partial_book_data.ts` - "processes partial data without losing diagnostic warnings".
